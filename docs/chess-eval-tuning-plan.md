### 1.2 当前评估的参数清单(逐行数出来的)

| 组 | 位置 | 可调标量 |
|---|---|---|
| 子力 `VAL_MG`/`VAL_EG`(P/N/B/R/Q) | 顶层数组 | 5 + 5 = **10** |
| PST `PST_MG`/`PST_EG`(6 子 × 64) | 顶层 2D 数组 | 384 + 384 = **768** |
| 兵结构:叠兵 / 孤立兵(MG/EG 各一) | `evaluate` 内联魔数 `12/22`、`14/16` | **4** |
| 王盾:每缺一兵(MG) | 内联魔数 `14` | **1** |
| 双象(MG/EG) | 内联魔数 `25/45` | **2** |
| **合计** | | **785** |

两个必须先处理的结构问题(不处理会直接让拟合失效):

1. **左右对称冗余** —— **逐表实测过(不是靠眼看,第一版这里我写错了)**,结果:

   | PST | 实测 | 处理 |
   |---|---|---|
   | 兵 MG | **不对称**:d4=75 vs e4=80、d3=40 vs e3=45 | **保留 64 格**(d/e 兵的区分是故意写的) |
   | 马 / 象 / 车 / 后 MG | 完全左右对称 | 镜像到 32 个半列格 |
   | 王 MG | **不对称**:b1=22 vs g1=26 | **保留 64 格**(易位侧偏好) |
   | 兵 / 马 / 象 / 车 / 后 / 王 EG | **六张全部左右对称** | 全部镜像到 32 格 |

   ⇒ MG 侧 `64 + 32×4 + 64 = 256`,EG 侧 `32×6 = 192`,**PST 合计 448**(原 768)。
   顺带核实:兵表第 1 横线与第 8 横线**全为 0 且不可达**,这 16 格在特征里恒为 0,
   覆盖度统计要排除掉,不能当"稀有格"去特殊处理。

2. **子力与 PST 精确共线**:对同一子类,`子力计数 = Σ_sq 该格计数`,所以"子力值 +c、PST 每格 −c"
   是完全等价的模型 —— 每个(子类,相位)存在一条 **1 维零空间**,共 5×2 = **10** 条。
   **→ 必须给每个(子类,相位)钉一个"可达"的参考格(系数固定为 0)**,例如兵的参考格取 a2、
   轻子取 a1。**注意参考格必须可达** —— 钉一个永远出现不了的格(比如兵在第 1 横线)等于没钉。

## 一·补 两个数据源:主用哪一个

仓库里现在有**两个**采样器,产出两套不同来源、不同许可的数据:

| | `sample-dataset.mjs`(**已跑完**) | `sample-lichess-dataset.mjs`(待跑) |
|---|---|---|
| 来源 | HF `ssingh22/chess-evaluations`(Kaggle chessData 转载) | `database.lichess.org` 官方评估库 |
| 许可 | 数据集标注 MIT(底层是 SF 的评估) | **CC0** |
| 规模 | train 307,000 / val 30,000(已生成并体检) | 目标 train ~30 万 / val 3 万(按相位配额) |
| 标签 | SF 评估 cp / mate | lichess 库里**深度最高**的 eval 的首条 PV,且**只保留 depth ≥ 20** |
| 附加字段 | 来源 id `s` | **`d`(depth)、`kn`(knodes)、`b`(相位桶)** |
| 采样 | 随机 row group | **按相位配额分层水库** |

### 决策:以 lichess(CC0)为主,Kaggle/SF 那套当交叉校验

理由三条:

1. **许可最干净。** 整站 CC0,连"数据集标注 MIT、底层是 SF 评估"这种还要解释一句的边界都没有,
   与仓库对 GPL 的一贯谨慎一致(`docs/chess-eval-upgrade.md` §四)。
2. **带 `depth` / `knodes`。** 可以明确"只用 depth ≥ 20 的标签",还能在拟合时按深度加权;
   Kaggle 那套没有这个字段,标签质量只能默认它可靠 —— 而 §2.3 已经指出这类标签本身就带搜索成分。
3. **相位配额分层,正好对上我们最大的识别性问题。** §1.2 第 2 条和 §6.3 都指出 MG/EG 结构性共线,
   EG 参数**只由低相位局面提供信息**,分层就是为这件事准备的。

**已经生成的那 30.7 万 Kaggle 局面不要浪费**:拿它做**独立复现** —— 两套数据各自拟一遍,
比 ① val 误差量级、② 两套权重的相关系数。**两套不同来源、不同引擎版本、不同局面分布的数据
如果拟出相近的权重,才说明拟的是棋理而不是某一家的癖好**;这比任何单一数据源的 val 误差都有说服力。

### 采样器要修两处(都便宜,但影响正确性)

1. **去掉 `bytes < MIN_SCAN_BYTES` 这个门。** 现在的水库替换只在扫描前 6 GiB(解压后文本)内进行,
   之后只计数不替换 ⇒ 池子是**整个文件的前缀样本**,不是全库均匀样本。而 `7z` 无论如何都要把
   ~129 GB 全解压一遍(扫描不会提前退出),**保留全程替换不多花一分钟**,白扔掉 95% 的流没道理。
2. **抬高低相位桶的配额。** 现在 5-9 子 26,000、2-4 子 6,000;但低相位局面是 **EG 参数的唯一信息来源**
   (每个局面给 EG 的权重是 `(24−phase)/24`,高相位局面接近 0)。EG 侧光 PST 就有 192 个参数,
   6,000 条平摊到每个参数只剩几十条。建议 5-9 子 → ~60,000、2-4 子 → ~25,000,总量 ~33.7 万 → **~45 万**。

### 成本(这是整条链路上唯一的"小时级"任务)

下载约 22 GB(压缩),解压流经约 129 GB 文本。`7z` 本机可用(NanaZip 7.0),C 盘余量 405 GB 够
(流式解压不需要落地 129 GB)。**建议尽早启动,别让它成为关键路径上的最后一环。**

## 二、决策一:用什么技术(拟合方法)

### 2.1 结论:监督蒸馏 + ridge 回归 + **闭式解**

手头的标签是 **Stockfish 的评估值**(cp / mate),不是对局结果。所以目标函数天然是
"让我们的评估逼近 SF 的评估",而不是 Texel 的"拟合对局胜负"。

**关键性质:我们的评估在待调参数上是严格线性的。** 相位插值不破坏线性 ——
`score = (mg·phase + eg·(24−phase))/24` 里 `phase` 只由**子力构成**决定、与参数无关,
所以展开后每个参数的系数是 `f_k(pos)·(phase/24)` 或 `f_k(pos)·((24−phase)/24)`,
**都只依赖局面本身**。连 `if (phase > 8)`(王盾)、`if (wb >= 2)`(双象)这种硬条件也一样 ——
它们只是"特征的选择开关",不引入对参数的非线性。

因此这是一个**线性最小二乘**问题,有闭式解:

```
w = (ΦᵀΦ + λI)⁻¹ Φᵀy
```

`Φ` 是稀疏特征矩阵(每行约 30 个非零)。**491 个参数 ⇒ `ΦᵀΦ` 是 491×491,
一趟扫描 30 万行就能建出来,秒级求解。** 不需要梯度、不需要学习率、不需要多轮迭代、
结果完全可复现。

**这就否掉了原文档里计划的"坐标下降"**:坐标下降是给"评估非线性 / 只能逐个参数试"的场景准备的;
我们是**凸**问题,坐标下降不仅慢得多,而且结果依赖迭代顺序,是**严格更差**的选择。
SPSA 同理(那是给参数多到无法求梯度、或评估不可微的场景用的)。

### 2.2 具体配置

| 项 | 决策 | 依据 |
|---|---|---|
| 目标 | 白方视角的 SF cp(mate 标签单独处理,见下) | 标签就是白方视角,拟合时把我们的走子方视角翻成白方视角 |
| 损失 | 平方误差(OLS) | 与闭式解匹配 |
| 正则 | ridge,λ 在 val 上扫一条网格选 | 处理 §1.2 的 MG/EG 结构共线 + 稀有 PST 格 |
| 目标裁剪 | **\|cp\| > 2000 的裁到 2000** | 只影响 s=0/1 的 **1.86% / 2.13%** 行,但 p99=5378/5916 会让它平方后**主导整个误差**(权重约 1700×) |
| mate 标签 | **不参与拟合**,单独记一份用作"我们是否在胜负已定局面同向"的对照 | `#+3` 这类标签是搜索结论,静态评估只需保证符号正确 |
| 稳健性 | 可选:裁完之后再做一遍 IRLS(Huber)重加权 | 尾部仍偏重时压一压 |

### 2.3 已知的局限(要写进结论里,不能宣称过头)

- **标签是 SF 的搜索评估,不是静态评估。** 整局局面里也有相当比例靠战术决定,静态评估匹配不了。
  裁剪 + 剔除 tactics 只能缓解,消不掉。这也正是**必须用自对弈做最终验收**的原因 ——
  "更接近 SF 的评分"不等于"更强"。
- **我们的特征集装不下 SF 的全部评估。** SF 有威胁、空间、王区、不平衡等一大堆项。
  我们拟合出来的是它在这个特征基下的**最佳近似**;要逼近得更好只能**同步加特征**(见 §3)。
- **尺度会变。** 拟合会让子力的绝对值浮动,而搜索里所有 margin(逆向 futility 95、futility 110、
  aspiration 35、SEE、MATE_B)都是按"100 cp = 1 兵"标定的。**必须做尺度锚定**(见 §4 的 S0-4)。

### 3.1·补 为什么机动性只有 8 个、通路兵只有 12 个(实测,`tuner/feature-collinearity.mjs`)

这两个数看着像随手给的。其实是**两条完全不同的约束**,而且**都允许往上加** —— 分开说。

**机动性:卡在结构上,不卡在样本上。**

按格给机动性表**在数学上是空的**:那张表第 k 列是 `m_k · 1[子在第 k 格]`(`m_k` 是该格的平均机动性,
是个常数),而 PST 第 k 列是 `1[子在第 k 格]` —— 两组列张成的空间**完全相同**,只差一个对角缩放。
⇒ 按格加机动性 = 给 PST 换个刻度,**新信息为 0**,ridge 只会把权重在这两处之间随便分掉。
PST 真正看不到的是**阻塞**(周围格子的占用),那是一个标量 / 子 / 相位 ⇒ 8 个。

实测这个标量**并不与 PST 共线**(把机动性对 64 个格子哑变量做饱和回归,20 万行):

| 子类 | 被"格子"解释 R² | 新信息 1−R² | VIF |
|---|---|---|---|
| 马 | **71.0%** | 29.0% | 3.45 |
| 象 | 33.0% | 67.0% | 1.49 |
| 车 | 32.2% | 67.8% | 1.47 |
| 后 | 43.4% | 56.6% | 1.77 |
| 兵 | 36.0% | 64.0% | 1.56 |

VIF 全部 < 3.5,加进去是安全的。马的 71% 是应有之义 —— 马的 PST 本来就是照机动性写的。

**8 是我们选的下限,不是数据允许的上限。** 机动性取值分布(每档样本量):

| 子类 | 取值范围 | 样本 <200 的取值 |
|---|---|---|
| 马 | 0..8 | 0 个 |
| 象 | 0..13 | 0 个 |
| 车 | 0..14 | 0 个 |
| 后 | 0..27 | 3 个(0 / 26 / 27) |
| 兵 | 0..2(近乎二值) | 0 个 |

⇒ N/B/R 的**每一档都撑得起 ≥200 行**,分段("曲线")版供得起。
所以决策是**分阶段**:先上线性版(8),拟合后看残差里有没有系统性曲率;有就升到
"每子每相位 2~4 个结点"(**16~32 个**)。反过来先上曲线版是拿参数去赌一个尚未验证的非线性。
(顺带:兵机动性只有 0/1/2 三个取值、近乎二值,不单列 —— 已由兵结构项覆盖。)

**通路兵:卡在样本量上,而且卡在杠杆最大的那一档。**

通路兵**确实**与 PST 不共线(是否通路取决于**敌兵结构**,不是格子),所以这 12 个是真新信息。
不能更细的理由纯粹是样本。按"自己那侧相对横线"统计(20 万行,两色合并):

| 相对横线 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|
| 兵次 | 21,601 | 23,530 | 34,754 | 34,256 | 17,853 | **7,722** |

再除以 2 个相位 ⇒ **第 7 横线每参数只剩 ~3.9k 行,是第 4 横线的 1/4**。而 SF 的 PassedRank 恰恰把
第 7 横线设成第 3 横线的 **16 倍** —— **最高杠杆的那一档样本最少**。任何进一步细分
(被保护 / 被阻挡 / 王距离)都是在这档上再做除法,所以先不做。
**12 = "横线 × 相位"的完整分辨率,已经是能站住的最大分辨率**,不是省的。

> 附带一条口径提醒:通路兵表按**自己那侧的相对横线**索引(白兵第 2 横线 ↔ 黑兵第 7 横线)。
> 统计和实现都必须先换成相对横线再合并两色,直接按绝对横线合并会把两色样本错位到相反的端点
> (第一版探针就是这么错的)。

### 3.2 tempo 放搜索层,不放 `evaluate()`

- 我们的 `evaluate()` 返回**走子方视角**,并且有"黑白镜像"的一致性要求;
  把 tempo 塞进 `evaluate()` 会变成一个恒定的加项,破坏这个对称性,也让"调参前后逐局面分数一致"这类验收没法写。
- SF 自己就是把 tempo 放在**搜索层**(`search.cpp` 里 `staticEval = eval + Tempo`),`evaluate()` 里没有。
- 具体做法:回归模型里给一个 `+1 / −1`(白方走 / 黑方走)的特征,让拟合去定它的值;
  跑搜索时 `staticEval = evaluate(pos) + TEMPO`,以走子方视角计就是恒加 `TEMPO`。

### 3.3 数据规模

481 个自由参数 ÷ 30.7 万 = 每参数 640 个局面,整体够;但 **PST 是逐格的**,
稀有格(如 a8 的马、h 线残局的兵)覆盖会掉到几百甚至几十条,拟出来就是噪声。三个动作:

1. **用 lichess 那套分层采样**(§一·补),总量 ~45 万:相位分层保证 **EG 参数**有足够样本,
   这是 Kaggle 那套随机采样给不了的。
2. **覆盖度闸门:训练集里出现次数 < 200 的 PST 格不参与拟合**,保持手写初值(或与相邻格捆绑)。
   反解之前先做一次覆盖统计。**兵表第 1/8 横线那 16 个恒零格直接排除**(已核实不可达)。
3. Kaggle 那套保持 30.7 万不动,专门当**独立复现**用(§一·补)。

### 3.4 明确**不**调的参数,和**不加**的项

**不调**(结构性/不可辨识):

- `PHASE_W` / `PHASE_MAX`/相位插值权重 —— 它与 MG/EG 的整体缩放**相互抵消**,一起拟合不可辨识。
  固定为现值;若确实想变,只能当超参在 val 上试。
- `if (phase > 8)` 的门槛、王盾的激活条件 —— 硬条件,当超参,不当参数。
- `MATE_B` / `INF` / aspiration `delta` / 各 futility margin —— 这些是**搜索**参数,不是评估参数(见 §4)。

**不加**(理由):

| 项 | 为什么不加 |
|---|---|
| 空间(space)、不平衡(imbalance) | 参数多、计算贵、对调参数据量要求高;在 9~10 层的小引擎上收益/成本比差。SF 有是因为它整体规模不同 |
| 完整威胁表(威胁兵/威胁轻子/威胁车) | 与"机动性 + 王区"高度重叠,先做那两项;等 A/B 显示还不够再加 |
| 易位权 | 王的 PST 已经奖励易位后的位置,易位权收益会随搜索自然体现;加了要处理"四档易位权"的编码,不值当 |
| 开局库 | 与体积约束冲突(整个引擎 worker chunk 现在 6.2 KB / 预算 35 KB,而 Wasabi 那份开局数据 369 KB) |
| NNUE | 见 `chess-ai-plan.md` §3.7,JS 标量执行会把 NPS 打下去一个数量级 |

> **只借结构与项的选择,不抄任何数值。** 上表里所有初值要么来自我们自己的手写表,要么**作为待拟合参数**产出。

## 四、决策三:搜索侧要改什么

这一节回答第二问。分三类:**调参的前置(必须做)**、**现在做(顺手且零风险)**、**明确推迟**。

### 4.1 前置:不做这些,调参无法进行

| 编号 | 动作 | 为什么是前置 | 验收 |
|---|---|---|---|
| **S0-1** | **参数化**:把 `VAL_MG/VAL_EG/PST_*/` 以及 `evaluate()` 里所有内联魔数(`12/22`、`14/16`、`14`、`25/45`)抽进一个 `EVAL_PARAMS` 表,`evaluate()` 只读它 | 调参器要能整体换一套权重 | **纯重构,数值一个不改**:`chess-engine-test.mjs` 67/67 + 逐局面分数与旧版完全一致 |
| **S0-2** | **特征导出** `evalFeatures(pos, out)`:按 §3.1 的布局输出特征向量;**与 `evaluate()` 共用同一份特征定义**(单一布局模块,禁止两处各写一遍) | 这是调参器唯一需要的接口;两套代码一定会漂移 | 对随机局面断言 `dot(features, w) === evaluate(pos)` |
| **S0-3** | **T1-1 攻击表基础设施**:兵/马/王按格表 + 预计算射线 | **机动性必须靠它**才能既正确又快;顺带省 5% NPS | 逐格对拍 640 组 + 逐局面四项全等(§9.7.1 已验证过一遍) |
| **S0-4** | **尺度契约**:把搜索里的 cp 尺度魔数(RFP `95`、futility `110`、aspiration `35`、SEE、`MATE_B`)抽成常量表,并写死规则:**调参后必须把权重整体缩放,使兵 = 100 cp** | 否则调完评估,搜索的所有 margin 都在错的尺度上,棋力会莫名其妙掉 | 缩放后 `evaluate(白兵) === 100`;67/67 |
| **S0-5** | `tempo` 挂到 `search`(`staticEval = evaluate(pos) + TEMPO`),`evaluate()` 保持对称 | §3.2 | 黑白镜像一致性用例通过 |
| **S0-6** | **安静局面判定接口**(给自对弈数据用):`qsearch` 返回值 == `evaluate()` 时才算安静 | 将来要生成自对弈 WDL 数据时必须过滤战术不稳定局面;对现在这批 SF 标签数据是可选过滤 | — |

### 4.2 现在顺手做(与调参互不干扰)

- **T1-1 的 S0-3 已经覆盖**(它是调参前置,同时是零风险提速)。落地后 master 档从 ~2.8s 更短,
  且**行为逐位不变**,不污染任何 A/B 口径。

### 4.3 明确推迟(以及为什么)

| 项 | 推迟到什么时候 | 为什么 |
|---|---|---|
| **所有 Tier 2 剪枝**(对数 LMR、LMP、razoring、futility 放宽、IIR、countermove) | **调参完成后**再重测 | §9.8 实测:这套东西在**当前**评估下同深度省 37~54% 节点、固定预算多 1.3 层,但 76 局自对弈**点估计反而落后 55 Elo**(区间 −22~+139)。本引擎是评估瓶颈,名义层数不值钱 —— 等评估强了,同样的剪枝才可能开始有正收益。**那时复用 §9.8 的 A/B 流程(冷置换表口径 + 仓库 67 项闸门)重跑。** |
| **T1-2 合法着法生成**(pinned/checkers 掩码) | 同上 | 是结构上最本质的一项(伪合法 + 逐着试 → 直接生成合法着法),但它是大改动、且**在固定节点预算下不换棋力**。放在评估这条线之后再评估 |
| **T1-3 增量 `evaluate`** | 调参全部结束后 | ⚠️ **它与调参直接冲突**:增量 eval 把"评估"做成"维护的累积量",而调参需要的是"给定局面重新算出特征向量"。现在做等于给自己上枷锁。而且速度在固定节点预算下不换棋力,没有做的理由 |

### 4.4 验收闸门(三档,都要过)

1. **正确性**:`chess-engine-test.mjs` 全部用例。
   ⚠️ 注意:第 0 阶段要求 **67/67 逐项不变**;但**评估数值一变,少数按分数阈值的断言就会挂**
   (例如 `r.score > 600`、`白吃后局面分应明显为正`)。这类断言是拿旧评估标定出来的,
   阶段 1 之后要**逐个判断**是"真的变弱"还是"阈值需要重标",**不许直接放宽阈值蒙过去**。
2. **拟合质量**:val 上的 MSE/R²,以及**逐项 sanity check** —— 兵值 ≈100(锚定后)、叠兵/孤立兵罚分为负、
   通路兵随横线单调增、机动性系数为正。**任何一项符号反了都要停下来查特征,而不是让拟合背锅。**
3. **棋力(唯一真判据)**:A/B 自对弈,新旧评估各一份、同样节点预算。
   **局数必须够**:§9.8 实测 **76 局的分辨率只有 ±127 Elo**,不足以判小改动。
   建议 **≥400 局**,并且**开局不能靠手写**(38 条不够)—— 改成"从基线引擎在开局前 8 个回合里
   按固定种子在 top-3 着法中随机分歧"批量生成,这样开局多样性与被测量的改动无关。

## 六、风险与不可辨识项(诚实清单)

1. **"更接近 SF 的评分" ≠ "更强"。** 这是蒸馏路线的根本局限。所以最终判据放在阶段 5 的自对弈,
   不在拟合误差上。
2. **标签本身带搜索成分。** 整局局面里也有一部分靠战术决定(裁到 ±2000 后仍有 4~5% 的 |cp|>1000)。
   这部分残差会通过 PST/子力项渗进来,无法完全消除。
3. **MG/EG 结构性共线。** 两者按 `phase/24` 混合,如果数据相位分布偏窄就会病态。ridge 只是**缓解**,
   所以必须**先看一相位分布**(采样器已经报了 25-32 子 / 17-24 子 / 10-16 子 / 5-9 子 / 2-4 子 五档占比)
   再决定 λ。
4. **王盾、双象这些"硬条件"项的样本量小。** 例如双象只在 `wb>=2` 时激活,王盾只在 `phase>8` 时激活 ——
   它们的有效样本远小于 30 万。拟合前要看这些子集的样本数,不够就别调(保持手写值)。
5. **搜索 margin 与评估尺度耦合。** 已在 S0-4 处理,但这是最容易在换权重后"悄悄变弱"的地方,
   阶段 4 后的 67/67 必须真跑,不能推理。
